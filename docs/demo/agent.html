Someone planted a miner.

The SRE has a time machine. Production does not get the first knife.

The attacker

A Deployment named node-agent - looks like a helper, burns a core as /tmp/nodecheck. The real app, k7-victim, is healthy. Hidden on the host: a respawner that puts the miner back whenever anyone deletes it. The inspect battery never names that respawner.

Three guesses, all wrong

The defender - Kimi K3 - clones the live cluster three ways and tries a cleanup in each copy.

CopyGuessAfter the soak
0000Delete itGone thirty seconds. Then it is back.

A cleanup that “works” is not a fix. The next search starts from 0000 - the copy that already knows delete is a lie - not from production.

One copy gets wrecked on purpose

Three more clones. 21 of 24 VMs live.

0003 restarts k3s with audit logging to catch who recreates the miner. It sees system:node do a client-side apply. The miner still returns in ~19 s. That universe now has a restarted control plane. Irreparable, and that is fine - it is a fork. Nobody rolls it back.

0004 tries “stop the guest agent, then delete.” The command times out. Another burned lab.

0005 deletes the miner and hangs an admission policy on the name node-agent. Manual recreate comes back denied. Victim still Ready. A long soak: still gone.

The win

Only then production. Same two moves that held on 0005: delete, lock the name. Soak. It does not come back. k7-victim is 2/2. Tetragon of the source is clean.

No rollback. The wrecked labs stay wrecked. The keeper is a door that stays shut. Production only sees the door.
